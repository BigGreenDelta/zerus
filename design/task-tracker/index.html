Project tasks · tiles

A task is the text of a prompt; it has no title. The Tasks tab sits next to Activity and Terminal: stage tiles on top, the list of the selected stage below. Tasks are created with the same input as Activity, without the Activity toolbar; a new task goes to To do, or to Backlog while the Backlog stage is open. The open session is the recipient. Nothing is sent automatically in this plan: you send a task yourself with Send now. The window, Activity, the input and its toolbar copy the current Zerus GUI: colours and sizes come from the source. Beside it, the Android app shows the same tasks with its own components. Both are clients of the same host: a change in one appears in the other.

How to use

  • A tile is a stage with its count. A click shows that stage's list; drop a task on the To do or Backlog tile to move it there.
  • Tasks of the open session are highlighted: pinned to it, or running, in review or done in it. The funnel hides the tasks of other sessions; Any session tasks stay. Counts follow, and the filter stays on while you switch sessions.
  • A row is the prompt text, two lines. Actions are icons on the right: they appear on hover and never move the text.
  • A new task goes into the input at the bottom of the Tasks tab. Enter or the button puts it in To do, or in Backlog while the Backlog tile is open; the button is named after that stage. The open session is the recipient.
  • A click on a task, or its pencil, opens the task settings: the prompt, the session (or Any session), the history and comments. Drag a To do or Backlog task onto a session in the list to give it to that session, or onto the project header to make it Any session.
  • If the agent needs you, it asks in its session as usual; the task stays In progress and its row shows the session status.
  • Send now pastes the task prompt and the task is In progress; Zerus does not check that it arrived and does not follow the session afterwards. If the session ends, the task stays In progress.
  • When the agent reports, the task moves to In review. You accept it into Done or send it back to To do. ✕ cancels a task In progress after a confirmation: it moves to In review, and its session gets the cancel message.
  • A task reaches an agent only through Send now or an agent's task_start; Zerus sends nothing on its own.

Android

  • The session screen gets a Tasks button in its tools row, with the number of tasks In review. It opens the project's tasks full-screen, like Terminal; Back returns to the conversation.
  • Stages are a scrollable tab row with counts, like the Session details tabs.
  • Tasks opens on the session of the conversation you came from; it receives new tasks and is highlighted. Session chips under the title pick another session for Tasks only, in one tap; each chip shows the session status. ⋯ opens a sheet with the sessions of other projects. Back returns to the conversation you came from.
  • A card shows the task text, its session and the same action icons as the desktop row, always visible. A tap, or the pencil, opens the task settings: the prompt, the session, the same actions, the history and comments.
  • The input is the app's message input; its button adds the prompt to To do, or to Backlog while the Backlog tab is open. Nothing is sent until Send now.
  • The agent's own plan stays in Session details, where its tab is renamed from Tasks to Plan.

Lifecycle

Backlog ⇄ To do — you press Send now → In progress (Zerus never sends on its own)
In progress — task_report → In review — you press Accept → Done (or Back to To do)
In progress — ✕ Cancel, confirmed in a dialog → In review; the session gets the cancel message, nothing else changes
There is no way from In progress straight to Done: a finished task goes through In review
The agent asks you something → it asks in its session; the task stays In progress
